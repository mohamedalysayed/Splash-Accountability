# Onboarding — new machine, hit the ground running

You cloned the repo on a new laptop. Here's the shortest path to a working dev environment + the ability to deploy.

---

## TL;DR — happy path (3 commands)

```bash
git clone git@github.com:<your-user>/Splash-Accountability.git
cd Splash-Accountability
# bring your .env from the old machine (see "Bring with you" below), then:
./setup.sh
./start.sh
```

`setup.sh` is idempotent — safe to re-run. It installs Python deps, dashboard deps, and initializes the SQLite dev DB. `start.sh` boots the agent, API, dashboard, and (if configured) an ngrok tunnel.

---

## What lives where

| Thing | Source of truth | Survives new clone? |
|---|---|---|
| Source code | GitHub | ✅ yes (`git clone`) |
| **Production secrets** | Fly (`flyctl secrets list -a splash-accountability-api`) | ✅ already deployed, untouched |
| **Production DB** | Fly volume mounted at `/app/data/accountability.db` | ✅ untouched |
| **Dashboard env (prod)** | Netlify site settings → Environment variables | ✅ untouched |
| Local dev `.env` | This file, gitignored | ❌ **bring from old machine** |
| Local dev DB (`data/accountability.db`) | Local file | ❌ throwaway, regenerated by `setup.sh` |
| `venv/`, `dashboard/node_modules/` | Local | ❌ regenerated by `setup.sh` |
| `data/avatars/*` (uploaded profile pics, local only) | Local | ❌ test data, ignorable |

**Translation:** prod is untouched no matter what you do on the new machine. The dev DB only contains test data — none of your real users live there.

## Bring with you

### Required for local development

- **`.env`** — copy from old machine. Contains: `ANTHROPIC_API_KEY`, `TWILIO_*`, `JWT_SECRET`, `USER_*`, `NGROK_AUTHTOKEN`, and Stripe keys if you've added them locally.

### Required if you want to deploy from the new machine

Install these CLIs and log in once:

- **`flyctl`** — `curl -L https://fly.io/install.sh | sh` → `flyctl auth login`
- **`gh`** — for pushing branches / PR review
- **`netlify-cli`** (optional — `npm i -g netlify-cli` then `netlify login`) — only needed if you want to trigger dashboard deploys from CLI. Otherwise Netlify auto-builds on git push.
- **`stripe`** CLI (optional) — only needed if you want to forward webhooks to local for debugging billing.

### Nothing else to import

Database, Stripe customers, Twilio config, ADMIN_EMAILS, etc. — all server-side. No file transfer needed.

## Disaster recovery — `.env` is lost

If you can't recover `.env` from the old machine, rebuild it from these sources of truth. Each line below corresponds to one env var:

| Env var | Where to get it |
|---|---|
| `ANTHROPIC_API_KEY` | https://console.anthropic.com/ → API Keys (create new, revoke old) |
| `TWILIO_ACCOUNT_SID` | https://console.twilio.com/ → top of dashboard |
| `TWILIO_AUTH_TOKEN` | https://console.twilio.com/ → top of dashboard |
| `TWILIO_WHATSAPP_NUMBER` | `+14155238886` (sandbox) — same for everyone |
| `STRIPE_SECRET_KEY` | https://dashboard.stripe.com/apikeys |
| `STRIPE_WEBHOOK_SECRET` | https://dashboard.stripe.com/webhooks → click endpoint → reveal |
| `GOOGLE_OAUTH_CLIENT_ID` | https://console.cloud.google.com/ → Credentials |
| `JWT_SECRET` | Generate fresh: `python3 -c 'import secrets; print(secrets.token_urlsafe(48))'` — **but only for local dev**. Don't change the Fly one or all prod users get logged out. |
| `NGROK_AUTHTOKEN` | https://dashboard.ngrok.com/get-started/your-authtoken |
| `USER_*` | Your name, your phone number in E.164, your IANA timezone |

Production secrets are independent — they're already set on Fly. You can list (digests only, not values) with `flyctl secrets list -a splash-accountability-api`. If you ever need to read a Fly secret's actual value, you can't — Fly only shows digests. Get it from the service console instead.

## Verify you're connected to prod (not just local)

```bash
flyctl auth whoami                                          # should be your Fly account
flyctl status -a splash-accountability-api                  # should show the running machine
curl -s https://splash-accountability-api.fly.dev/health    # should return {"status":"ok",...}
gh auth status                                              # should show GitHub login
```

If all four pass, you can deploy with:

```bash
flyctl deploy -a splash-accountability-api --remote-only
```

Dashboard deploys are automatic on `git push origin main` (Netlify build hook).

## First-time prod ops cheatsheet

```bash
# Tail prod logs
flyctl logs -a splash-accountability-api

# SSH into prod container (sqlite3 CLI isn't installed; use python instead)
flyctl ssh console -a splash-accountability-api

# Query prod DB
flyctl ssh console -a splash-accountability-api -C "python -c \"from db import get_session, User; s=next(iter([get_session().__enter__()])); [print(u.id, u.email, u.tier, u.is_admin) for u in s.query(User).all()]\""

# Set / update a prod secret
flyctl secrets set FOO=bar -a splash-accountability-api

# Trigger a redeploy (e.g. after secret change — Fly does this automatically too)
flyctl deploy -a splash-accountability-api --remote-only

# Promote a user to lifetime (admin override; webhook-immune)
flyctl ssh console -a splash-accountability-api -C "python -c \"from db import set_user_tier; print(set_user_tier(<id>, 'lifetime'))\""
```

## Things that will probably bite you

- **`.env` line endings** — if you copy `.env` from Windows, run `dos2unix .env` or `sed -i 's/\r$//' .env`. `source` will silently misparse otherwise.
- **`venv` is platform-specific** — never copy `venv/` between machines. Always let `setup.sh` regenerate.
- **`data/accountability.db` is dev-only** — if you accidentally edit it thinking it's prod, no harm done. Prod DB is on the Fly volume, not in your repo.
- **Twilio sandbox needs a re-join** — every 72h, you have to text `join <code>` to `+14155238886` again. The code is in your Twilio console.
- **Don't regenerate `JWT_SECRET` on Fly** — it invalidates every issued token. All prod users get logged out.
